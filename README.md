# КАДР

Статичний сайт кінотеатру. Відкрийте `index.html` у браузері або запустіть сайт через Live Server.

- `index.html` — головна сторінка та афіша.
- `pages/movies/` — окремі сторінки шести фільмів.
- `pages/register.html` — реєстрація та вхід за кодом із листа або через Google. Перехід доступний у вікні налаштувань. Для реальних листів і Google потрібно налаштувати Supabase за інструкцією нижче.
- `assets/js/auth-config.js` — публічні налаштування проєкту Supabase.
- `assets/js/auth.js` — надсилання та перевірка коду, Google OAuth, відновлення сесії та вихід на всіх сторінках.
- `assets/js/tickets.js` — надсилання квитків із вікна оформлення та перегляд квитків на сайті.
- `supabase/functions/send-tickets/` — серверна перевірка акаунта, каталог місць і поштовий шаблон квитка.
- `assets/css/register.css` — адаптивні стилі сторінки реєстрації.
- `assets/css/style.css` — спільні стилі та теми.
- `assets/css/movie.css` — стилі сторінок фільмів.
- `assets/js/components/layout.js` — спільний хедер і футер. Зміни тут застосовуються на всіх сторінках.
- `assets/js/theme.js` — відновлення теми перед відображенням сторінки.
- `assets/js/common.js` — перемикання теми та мобільне меню.
- `assets/js/i18n.js` — англійські переклади, перемикач мови та оновлення динамічних підписів.
- `assets/js/home.js` — карусель головної сторінки з фрагментами трейлерів через YouTube IFrame Player API без звуку; наступне відео готується під час показу попереднього та продовжує відтворення при перемиканні без перезапуску. Одночасно відтворюються лише поточний і наступний фрагменти.
- `assets/js/movie.js` — вибір місць у залі та трейлери через YouTube IFrame Player API.
- `assets/images/` — локальні постери та зображення трейлерів; `sources.json` містить посилання на їхні джерела.

На головній сторінці показується один фільм. На екранах від 700 px відео та опис розташовані поруч, на вузьких — опис під відео. Банери відтворюють фрагменти трейлерів через YouTube API без звуку, кнопок програвача та взаємодії з YouTube при натисканні. Джерело і початок фрагмента задаються атрибутами `data-video-id` і `data-clip-start` в `index.html`. Фільм і опис змінюються разом кожні 10 секунд; кнопка «Пауза» зупиняє лише автоперемикання слайдів, а відео продовжує відтворюватися по колу без звуку. Карусель також зупиняється, коли вкладка прихована, фокус перебуває всередині слайда або ввімкнено налаштування зменшення руху. При прихованій вкладці відео зупиняється; при зменшенні руху, недоступному YouTube або відкритті через `file://` показується локальне зображення. Для відео потрібні інтернет і HTTP/HTTPS (наприклад, Live Server).

Фільми можна вибирати кнопками-індикаторами під каруселлю або горизонтальним свайпом на сенсорному екрані. Зображення також можна перетягнути мишею. Для перемикачів доступні клавіші ←/→, Home та End. Після ручного перемикання відлік 10 секунд починається заново; ручне керування працює і під час паузи.

На всіх шести сторінках фільмів додано трейлери. Вони запускаються без звуку; натискання на кнопку «Увімкнути звук» над відео вмикає звук. Для вбудованих трейлерів потрібні інтернет і запуск через HTTP/HTTPS (наприклад, Live Server): YouTube може відхиляти програвачі, відкриті через `file://`. Якщо браузер блокує автозапуск, відео можна запустити натисканням. API не потребує ключа; ID трейлера задано в атрибуті `data-video-id` секції `.movie-trailer` відповідної HTML-сторінки.

Під описом кожного фільму є квадратна кнопка «⋯»: вона розгортає оригінальну назву, рік виходу, режисера, тривалість, жанр і список основних акторів. Для «Думками навиворіт 2» зазначено акторів оригінального озвучення. Повторне натискання приховує деталі; керування доступне мишею, дотиком та клавішами Enter / пробіл і працює без JavaScript завдяки `details` / `summary`. У кожному блоці є посилання на офіційну сторінку фільму. Дані містяться в HTML відповідної сторінки, стилі — в `assets/css/movie.css`.

Кнопка «Налаштування» у хедері відкриває вікно з реєстрацією, анімованим перемикачем теми та перемикачем мови UA / EN у такому самому стилі. Вікно закривається кнопкою ×, клавішею Escape або натисканням за його межами. На мобільному кнопка налаштувань показується іконкою. Тема та мова зберігаються у `localStorage` і відновлюються на інших сторінках; перемикання доступне і без сховища. Англійський переклад охоплює головну, сторінки фільмів, реєстрацію, схему залу, оплату, підказки та повідомлення. Мова інтерфейсу не змінює мову дубляжу чи трейлерів. За налаштування зменшення руху анімацію вимкнено. Для стабільного збереження між усіма сторінками використовуйте Live Server: поведінка сховища для `file://` залежить від браузера.

На сторінках фільмів вільні місця підсвічуються при наведенні та вибираються натисканням або клавішами Enter / пробіл. Вибране місце стає сірим; повторне натискання скасовує вибір. Зайняті місця недоступні. У залі 6 звичайних рядів по 10 місць і 2 VIP-ряди по 4 просторі дивани. Кожен диван продається як одне VIP-місце, дорожче на 100 ₴. В афіші та розкладі вказано ціну звичайного місця; обидві ціни показано біля схеми залу.

Після вибору з’являється кнопка «Оплатити» із загальною сумою звичайних та VIP-місць. У цьому блоці показується список до чотирьох вибраних місць. Якщо вибрано більше чотирьох, замість списку з’являється загальна кількість вибраних місць і кнопка «⋯», яка відкриває всі місця із цінами й загальною сумою. У списку є кнопка «До оплати» для переходу до вікна оплати. Кнопка «Оплатити» відкриває його одразу. Обидва вікна закриваються кнопкою, клавішею Escape або натисканням за межами вікна; вибрані місця зберігаються. Реальна оплата та бронювання ще не підключені, платіжні дані не збираються. Вибір діє до оновлення сторінки.

Під час додавання фільмів спочатку шукаємо трейлер з українським озвученням; якщо його не знайдено, використовуємо англійський. Мову зазначено в заголовку секції трейлера. Поточні джерела:

- [Думками навиворіт 2 — українською](https://www.youtube.com/watch?v=71Tq0CCCZdE).
- [Бетмен — українською](https://www.youtube.com/watch?v=zC6-H-EcEmU).

Хедер і футер додаються через JavaScript без запитів `fetch`. Розклад і ціни демонстраційні. Постери та зображення збережено локально, використовується системний шрифт. Зовнішнє підключення потрібне для трейлерів YouTube та карти Google.

## Кінотеатри поруч — Google Maps

На головній сторінці є компактна квадратна карта та кнопка «Знайти поруч». Посилання «Кіно поруч» у хедері й мобільному меню веде до цього блоку. Браузер запитує геолокацію тільки після натискання кнопки; координати не зберігаються на сайті.

API-ключі, Google Cloud і платіжний обліковий запис не потрібні. Карта Google вбудована через iframe, а список кінотеатрів завантажується з відкритих даних [OpenStreetMap](https://www.openstreetmap.org/copyright) через [Overpass API](https://overpass-api.de/). Це різні джерела: результати на карті Google та в списку можуть відрізнятися.

Для запуску відкрийте сайт через Live Server на localhost або через HTTPS, натисніть «Знайти поруч» та дозвольте геолокацію. Потрібен інтернет; додаткове налаштування не потрібне.

Пошук охоплює об’єкти `amenity=cinema` будь-яких мереж: точки, будівлі та відношення. Показує до п’яти найближчих кінотеатрів у радіусі 20 км; якщо результатів немає, радіус збільшується до 50 км. Відстань обчислюється по прямій. Назва відкриває координати кінотеатру в Google Maps, а «Прокласти маршрут» — маршрут від користувача.

Повнота списку залежить від даних OpenStreetMap. Публічні сервери Overpass можуть бути перевантажені: запити мають таймаут і резервний сервер. За помилки або відмови в геолокації залишається доступним посилання Google Maps. Координати передаються Google для карти й Overpass для пошуку, але не зберігаються на сайті. Логіка — `assets/js/cinemas.js`, стилі — `assets/css/cinemas.css`.

Дизайн оновлено з орієнтиром на [Netflix](https://www.netflix.com/ua/), [Multiplex](https://multiplex.ua/) та [Prime Video](https://www.primevideo.com/storefront/home/home): компактна навігація, справжні постери, темна та світла теми, червоні кнопки дій, ряд афіші й прямі переходи до сеансів і трейлерів. На широких екранах афіша має шість колонок, на середніх — три, на вузьких — дві.

## Налаштування реєстрації та входу

Інтеграція використовує Supabase Auth. Новий акаунт створюється при вході через Google або підтвердженні електронної пошти одноразовим кодом. Після входу «Реєстрація» в налаштуваннях замінюється на «Вийти з акаунта». Сесія відновлюється після переходів між сторінками та перезавантаження; вихід завершує сесію в цьому браузері, включно з іншими вкладками сайту.

1. Створіть проєкт у [Supabase](https://supabase.com/dashboard). У `assets/js/auth-config.js` заповніть `url` (Project URL) та `publishableKey` (publishable key або legacy `anon` key). Ці значення публічні; `service_role`, secret key, SMTP-пароль та Google Client Secret у файли сайту не додавайте.
2. У Authentication → Sign In / Providers увімкніть Email і дозвольте створення нових користувачів. Налаштуйте строк дії та довжину Email OTP (форма підтримує 6–10 цифр).
3. У Authentication → Email Templates замініть вміст **Magic Link** і **Confirm signup** на лист із кодом, наприклад:

   ```html
   <h2>Вхід до КАДР</h2>
   <p>Ваш одноразовий код: {{ .Token }}</p>
   <p>Введіть його на сторінці реєстрації.</p>
   ```

   Без цієї зміни Supabase за замовчуванням надсилає посилання замість коду. [Документація Email OTP](https://supabase.com/docs/guides/auth/auth-email-passwordless).
4. Підключіть власний SMTP у налаштуваннях Authentication: вбудований поштовий сервіс обмежений і призначений для тестування, тому для листів довільним користувачам потрібен власний провайдер. [Налаштування SMTP](https://supabase.com/docs/guides/auth/auth-smtp).
5. У Authentication → URL Configuration задайте Site URL і додайте точну адресу `pages/register.html` до Redirect URLs для кожного середовища, наприклад `http://localhost:5500/pages/register.html` та `https://your-domain.example/pages/register.html`. Якщо сайт у підкаталозі, включіть його в адресу. Користуйтеся тим самим хостом і портом протягом входу.
6. У Google Cloud створіть OAuth client типу Web application і налаштуйте consent screen. Authorized JavaScript origins — адреса сайту без шляху; Authorized redirect URI — callback Supabase `https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback`. У Supabase увімкніть провайдера Google та внесіть Client ID і Client Secret у його налаштування. Якщо Google app у режимі Testing, додайте користувачів до Test users. [Документація Google OAuth](https://supabase.com/docs/guides/auth/social-login/auth-google).
7. Запустіть сайт через Live Server на localhost або HTTPS. Введіть пошту, отримайте код, підтвердьте його. Окремо перевірте Google, перехід на сторінку фільму, перезавантаження й вихід з акаунта. Повторне надсилання коду доступне через хвилину; помилковий чи прострочений код не дає увійти.

Поки конфігурація порожня, сайт показує недоступність входу й вимикає кнопки авторизації. Імітації листів або локальних акаунтів немає. SDK Supabase завантажується з jsDelivr лише після заповнення конфігурації; потрібен інтернет. Google використовує PKCE; сесію зберігає SDK Supabase у сховищі браузера. Для `file://` авторизація недоступна.

Автоматична перевірка: `node --test tests/auth.test.cjs`. Тести використовують імітацію відповідей провайдера для перевірки станів форми, помилок, виходу та OAuth callback; реальні листи й Google перевіряйте після підключення свого проєкту.

## Квитки на електронну пошту

На сторінках усіх шести фільмів виберіть місця та відкрийте вікно оформлення. Спочатку у вікні є кнопка «Оплатити». Після її натискання користувач, який увійшов через пошту або Google, бачить кнопку «Надіслати квитки на пошту», а гість — перехід до входу. Натискання «Оплатити» зараз підтверджує лише демонстраційну оплату: гроші не списуються. Зміна місць або акаунта скидає цей етап. Для кожного вибраного місця формується окремий квиток; усі квитки замовлення надсилаються одним листом на підтверджену пошту акаунта. Квитки також відображаються у вікні оформлення після прийняття листа поштовим сервісом.

Поля квитка розташовані в такому порядку:

```text
Номер квитка: KADR-унікальний_номер
Номер місця: Ряд 1, місце 1 (звичайне)
Вартість: 220 ₴
Назва сеансу: Дюна: Частина друга · 18:30
Тривалість: 166 хв
```

Зараз квитки **демонстраційні**: оплата та бронювання ще не реалізовані. Лист і вікно оформлення це зазначають. Після підключення оплати видачу справжніх квитків потрібно запускати з перевіреного серверного webhook успішного платежу та пов’язувати із збереженим замовленням і бронюванням. Самої кнопки в браузері для цього недостатньо.

### PDF-квитки

До листа додається файл `kadr-tickets-<requestId>.pdf` із MIME-типом `application/pdf`. На кожне місце у файлі є окрема сторінка A5 з полями у заданому порядку. Українські літери та знак гривні підтримує вбудований шрифт Noto Sans; для генерації PDF сервер не завантажує шрифт з інтернету. Текстова й HTML-версії листа залишаються доступними.

Генератор — `supabase/functions/send-tickets/pdf.mjs`. Шрифт і ліцензія SIL OFL — у `supabase/functions/send-tickets/fonts/`. Приклад готового файлу — [docs/ticket-example.pdf](docs/ticket-example.pdf). Згенерувати приклад повторно: `node scripts/preview-ticket-pdf.mjs`. Для локальних перевірок встановіть залежності через `npm.cmd ci`, потім виконайте `npm.cmd test`. PDF-тести перевіряють фактичний текст PDF, кількість сторінок, перенесення назв та ідентичні байти вкладення при повторі запиту.

Щоб PDF почав надходити в листах, повторно розгорніть `send-tickets` командою нижче з кореня проєкту. CLI використає `supabase/config.toml` та import map `supabase/functions/send-tickets/deno.json` для залежностей pdf-lib і fontkit. Налаштування поштових секретів та SQL змінювати не потрібно. Для перевірки створіть нове оформлення: вже успішно надіслані замовлення повторно не відправляються.

Вкладення передається Resend у Base64 відповідно до [документації вкладень](https://resend.com/docs/api-reference/emails/send-email). Якщо PDF не вдалося сформувати, лист не надсилається; повертається `pdf_generation_failed`. PDF має сталу метаінформацію, щоб повтор одного запиту генерував ті самі байти вкладення й зберігав сумісність із захистом від дублювання.

### Запуск надсилання

Публічного ключа Supabase та SMTP для входу недостатньо для надсилання квитків. Для цієї функції підготовлена інтеграція [Supabase Edge Functions + Resend](https://supabase.com/docs/guides/functions/examples/send-emails).

1. Створіть акаунт у [Resend](https://resend.com), підтвердьте домен відправника та створіть API key. Тестовий відправник Resend має обмеження одержувачів; для листів усім користувачам потрібен підтверджений домен.
2. У Supabase → SQL Editor створіть New query, вставте весь вміст файлу `supabase/migrations/202610100001_ticket_email_jobs.sql` і натисніть Run. Він створює журнал відправлень і функцію `claim_ticket_email`, встановлює права та оновлює кеш схеми API. Скрипт можна запускати повторно: збережені квитки не видаляються. Таблиця закрита для доступу з браузера.
3. У Supabase → Edge Functions → Secrets додайте:
   - `RESEND_API_KEY` — ключ Resend.
   - `TICKETS_FROM_EMAIL` — наприклад `КАДР <tickets@your-domain.example>` з підтвердженим доменом.
   - `ALLOWED_ORIGINS` — додаткові адреси сайту без шляху, через кому; наприклад `https://your-domain.example`. `http://localhost:5500` і `http://127.0.0.1:5500` уже дозволені у коді функції для Live Server. Якщо використовуєте інший порт, додайте його адресу.
   Значення `SUPABASE_URL` і `SUPABASE_SERVICE_ROLE_KEY` Supabase надає серверній функції автоматично. Ключі поштового сервісу та service role не додавайте до `assets/js/`.
4. Розгорніть функцію `send-tickets` через Supabase CLI з кореня проєкту:

   ```powershell
   npx supabase login
   npx supabase functions deploy send-tickets --project-ref ivxmmadtmedbfrbuqzrq --no-verify-jwt
   ```

   Конфігурація `supabase/config.toml` вимикає стару перевірку JWT шлюзом для цієї функції, а сам обробник обов’язково перевіряє токен через `auth.getUser(token)` перед створенням квитків. Це підтримує також асиметричні ключі підпису Supabase. Анонімні запити квитків відхиляються.
5. Увійдіть на сайті, виберіть звичайне та VIP-місце, відкрийте оформлення, натисніть «Оплатити», а потім — надсилання. Перевірте вхідні листи та «Спам». Повідомлення на сайті підтверджує прийняття поштовим сервісом, а не фактичне доставлення; стан доставлення доступний у Resend.

Якщо браузер показує `Response to preflight request doesn't pass access control check`, перевірте у Network відповідь `OPTIONS` на `/functions/v1/send-tickets`. `404` з `NOT_FOUND` / `Requested function was not found` означає, що функція ще не розгорнута або її bundle недоступний; [Supabase описує цю причину помилки CORS](https://supabase.com/docs/guides/troubleshooting/edge-function-404-error-response). Потрібно виконати команду deploy вище після входу у свій акаунт Supabase. `401` від шлюзу може означати увімкнену стару перевірку JWT — розгорніть із `--no-verify-jwt`; сам обробник продовжує перевіряти користувача. Для дозволених адрес функція відповідає на `OPTIONS` статусом `204` до перевірки акаунта та поштових секретів. Зміни у локальному коді функції застосовуються на сервері лише після deploy.

Сервер бере одержувача з підтвердженого акаунта, а ціну, назву, час і тривалість — з `supabase/functions/send-tickets/catalog.json`. Дані одержувача та ціни з браузера не використовуються. На акаунт дозволено до п’яти нових запитів квитків на годину. Повтор після збою використовує той самий request ID, квитки та [ключ ідемпотентності Resend](https://resend.com/docs/dashboard/emails/idempotency-keys), щоб уникнути дублювання листів. Повторну спробу сервер дозволяє через 30 секунд; автоматичні повтори через 23 години блокуються. Після перезавантаження сторінки або створення іншого замовлення надсилання вважається новим запитом.

Якщо змінюєте фільми, тривалість, сеанси, ціни чи місця в HTML, виконайте `node scripts/build-ticket-catalog.cjs` та повторно розгорніть `send-tickets`. Шаблон листа — `supabase/functions/send-tickets/tickets.mjs`; лист має HTML і текстову версію. Перевірки: `node --test tests/auth.test.cjs tests/tickets.test.mjs tests/ticket-ui.test.cjs`. Тести не надсилають справжніх листів. SQL і функцію потрібно розгорнути у вашому Supabase; без цього або без секретів надсилання покаже помилку.

### Помилка 503 при надсиланні квитків

У Network відкрийте відповідь POST `send-tickets`. Сервер повертає окремі коди, щоб відрізняти причини:

- `email_not_configured` — додайте `RESEND_API_KEY` і `TICKETS_FROM_EMAIL` у Supabase → Edge Functions → Secrets. Поле `missing` перелічує відсутні назви без значень секретів. Відправник має належати підтвердженому домену Resend.
- `server_not_configured` — серверній функції бракує `SUPABASE_URL` чи `SUPABASE_SERVICE_ROLE_KEY`, які має надавати Supabase.
- `ticket_storage_unavailable` — виконайте весь файл `supabase/migrations/202610100001_ticket_email_jobs.sql` у SQL Editor. Для перевірки наявності об’єктів: `select to_regclass('public.ticket_email_jobs'), to_regprocedure('public.claim_ticket_email(uuid,uuid,text,text,jsonb)');` — обидва результати мають бути непорожніми. У новій відповіді помилки `stage: claim` означає збій створення/отримання відправлення, `stage: save` — збій запису результату після прийняття листа сервісом. `database_code: PGRST202` означає, що API не бачить потрібної SQL-функції, `PGRST205` або `42P01` — таблиці. За наявних об’єктів виконайте `notify pgrst, 'reload schema';`. [Оновлення кешу схеми Supabase](https://supabase.com/docs/guides/troubleshooting/refresh-postgrest-schema).
- Старий `service_unavailable` — повторно розгорніть актуальний код, щоб отримати точнішу діагностику.
- `BOOT_ERROR` від платформи — функція не змогла запуститися; відкрийте її Logs у Supabase. Це відрізняється від кодів, які повертає наш обробник. [Діагностика 503 Supabase](https://supabase.com/docs/guides/troubleshooting/edge-function-503-response).

`OPTIONS 204` із `Access-Control-Allow-Origin: http://127.0.0.1:5500` означає, що CORS для Live Server працює. Якщо одночасно бачите старий запис CORS і новий POST 503, очистіть консоль та повторіть одну спробу: поточна причина може бути в налаштуваннях сервера, а не CORS. Після зміни коду функції виконайте deploy з інструкції вище. Секрети зберігайте на сервері, а не в `auth-config.js`.

## Майбутнє

- Зробити назви фільмів та інші дані динамічними, щоб редагувати їх у JSON.
- Підключити оплату й бронювання; видавати справжні квитки автоматично після підтвердженого сервером платежу.
- Додати реєстрацію та вхід за номером телефону з одноразовим кодом у Telegram. Потрібен серверний Telegram-бот, прив’язка й підтвердження номера через контакт користувача в боті, короткочасні коди та обмеження спроб/надсилань. Самого номера недостатньо, щоб бот міг надіслати повідомлення: користувач спочатку має розпочати діалог із ботом. Токен бота та перевірку кодів зберігати на сервері.
